# Profiles and Smart Defaults Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Settings profiles (SET-10) and work type suggestions (WT-7); RUN-5 recorded as covered.

**Spec:** `docs/superpowers/specs/2026-11-25-profiles-design.md`

## Global Constraints

- At most 10 profiles; a profile never holds a key, only `api_key_ref`; a switch is all or nothing.
- Work type changes only while a notebook has no outputs; suggestions by fixed rules only.
- Lines ≤ 120; files ≤ 500 (tests ≤ 800); coverage ≥ 80 %; every change updates docs.

## Review Focus

- Switching profiles keeps edits made to the active one (Task 1).
- A profile whose providers no longer validate: the switch is refused and nothing changes (Task 1).
- Deleting the active profile: settings stay, no profile is active (Task 1).
- Changing the work type after an output exists: refused (Task 2).
- A notebook with no sources or only disabled ones: no suggestion (Task 2).

### Task 1: Profiles (core, API, CLI)
- `config.Profile`, `File.Profiles`, `File.Profile`; checks. Service `Profiles()`, `SaveProfile(name)`,
  `UseProfile(name)`, `DeleteProfile(name)`; routes `GET/POST /v1/profiles`, `POST /v1/profiles/{name}/use`,
  `DELETE /v1/profiles/{name}`; CLI `tess profile`.
- Commit `feat: settings profiles`.

### Task 2: Work type suggestion (core, API, CLI)
- `service.SuggestWorkType(id) (WorkTypeSuggestion, error)`; `NotebookUpdate.WorkType`; route; CLI
  `tess notebook worktype`.
- Commit `feat: suggest a work type from the sources`.

### Task 3: Desktop
- Settings → Profiles (`profile-save`, `profile-use-<n>`, `profile-delete-<n>`), status bar profile; Sources tab
  suggestion notice (`worktype-switch`, `worktype-dismiss`).
- Commit `feat(desktop): profiles and work type suggestions`.

### Task 4: Docs and checks
- api.md, user guide, checklist (SET-10, WT-7, RUN-5), architecture; `task ci`.
- Commit `docs: profiles and smart defaults`.
